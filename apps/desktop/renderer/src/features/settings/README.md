# Settings feature

`SettingsPage.jsx` owns the full-workspace page, category navigation, dirty-state close guard, and status footer. The page owns its data: it re-fetches settings once on mount into its own snapshot, and the draft plus saved baseline derive from that snapshot — the app-level `settings` state is only a read-through cache that section saves patch via the saved response. The workbench stays mounted but hidden while this page is active. Model configuration has two sub-tabs: 模型资源池 (connections with their models) and 模型组. There is no global save: each tab saves itself — 模型组 commits groups/default/retry, 项目与 Agent commits workspace/agent (keeping the workspace-switch agent reset and refreshing the workbench on change), 运行与权限 commits steps/context/approvals, and connections save per connection through each editor's own head 保存 button. Section saves commit their draft fields over the shared saved baseline, so unsaved edits in other tabs always survive. Partial model states persist on purpose: Pygent only executes complete configurations, so a connection without models, or models outside every 模型组, is saved and reported as `unconfigured` (chat stays disabled with `model_configuration_required`) until the group tab completes the chain.

- `useSettingsDraft.js`: shared draft state, catalog loading, and group edit operations.
- `settingsModel.js`: native draft conversion, factories, validation, and `commitConnectionBuffer` (the pure merge of a connection editor buffer back into a draft).
- `AddModelForm.jsx`: the add-model form for one connection; it discovers the connection's models automatically, keeps manual ID entry as a fallback, and never assigns model-group membership.
- `ConnectionSettings.jsx`: the merged pool. Every row has one identical head in collapsed and expanded states — plain name text (double-click renames custom providers; a new connection renders the provider as a select box until one is chosen), a caret that opens the provider switch menu, 接口/模型 count badges, 添加接口, a 保存 button that stays visible but grays out until the connection fields change (it commits connection fields plus connection-owned protocol remaps), a 放弃 button whenever the row has unsaved changes, and 删除 — and a collapsed row shows nothing else. Each model row has its own 保存 button (gray when the model matches the saved state, disabled while the connection itself has unsaved fields) and commits independently, so an in-progress model never blocks another one. The trash icon only marks a saved model for deletion (将删除 badge, click again to unmark) and the row's 保存 commits the deletion; unsaved rows leave the buffer at once. Saving an existing row keeps the editor open so models stay testable; only the create form closes on its first save. A row expands in place with an animated `grid-template-rows` shell, several rows can be open at once, and every editor stays mounted so folding keeps its buffer. Each editor owns a buffer, its head, and the connection's model management (add, delete, identity, capabilities); the connection test lives inside 高级配置. Adding a model or clicking a folded row's discover button expands that row so the results are visible. Model UI never mentions model groups; membership is selected in the group tab.
- `GroupSettings.jsx`: group membership, default group, ordered fallback management, and a collapsible global retry policy (attempt count and idle timeout).
- `WorkspaceSettings.jsx` and `RuntimeSettings.jsx`: project defaults and execution/permission settings.
- `settings.css`: feature layout and responsive styles; shared form primitives remain in the app stylesheet.

Each connection editor keeps its edits in a local buffer, so saving one connection never carries another connection's or another section's pending edits. The save payload is built from the last persisted baseline plus this connection's slice (`commitConnectionBuffer`); App settings state stays untouched so unsaved workspace/group edits survive. Renaming a model remaps its model-group membership at commit time, and deleting a model drops it from every group. Connections with models cannot be deleted; models can always be deleted. Adding a model creates an ordinary native model record without group membership. Payload serialization remains in the existing shared API client.

Tests in `settingsModel.test.mjs` cover buffer commit semantics, provider switching, protocol changes, and discovery requests. App render tests retain coverage through compatibility exports in `App.jsx`.

ModelCapabilitiesEditor presents one capability-template selector (purpose presets and Pygent catalog models), actual capability tags, and all native Pygent capability fields in detailed controls. modelCapabilities.js preserves limits on template changes and enforces streaming/output and reasoning dependencies. Purpose names remain UI-only; saved native capability structure is unchanged.

Connection editors render in two modes, both showing the same read-only rows: an `API Key` row (configured badge plus the credential env name, or 无需认证) and one summary row per endpoint (`协议 · base_url`). A pencil turns the key row or one endpoint row at a time into its inline editor — password input with the 无需认证 switch, or `协议 + Base URL` inputs with delete. Both modes offer a connection test inside 高级配置 (credential reference, proxy, TLS), per-model discovery inside each model row. New connections receive a unique credential reference plus one OpenAI Chat Completions endpoint. Existing multi-protocol connections retain and display every endpoint.

A model's protocol selector appears only when its connection offers more than one protocol or the saved protocol is no longer configured; single-protocol models render no protocol selector. Models with an empty model ID start expanded so the missing field is obvious.

The connection editor switches providers from the head caret menu. Selecting a Pygent built-in provider applies its catalog protocols, default URLs, and credential name while carrying an unsaved API key to the new credential reference. Selecting Custom keeps the current endpoints for manual editing. Each endpoint edits as one `protocol + Base URL` row; changing its protocol updates the buffer's models that reference that endpoint, and endpoints still referenced by a model cannot be removed.
